Does FP8-aware (QAT) fine-tuning beat normal fine-tuning when the model is deployed in FP8?

Qwen2.5-0.5B-Instruct fine-tuned on GSM8K (grade-school maths). Full-model fine-tuning, NVIDIA H100. Accuracy on the complete 1,319-question GSM8K test set.

Bottom line. QAT-trained models keep more of their accuracy after being converted to FP8. After conversion they score +1.5 points higher than normally fine-tuned models in the 3-epoch experiment (better in 5 of 5 runs) and +0.9 points higher in the 1-epoch experiment (better in 3 of 5 runs).

How sure are we? The direction is consistent, but with one 1,319-question test set the size of the gain cannot be pinned down: the 95% intervals (-0.2 to +3.0 and -0.9 to +2.6 points) both reach zero. The most reliable evidence is the model's loss, where FP8 conversion hurts QAT models roughly half as much or less (details below).

1. What was tested

  • The question: models are often shrunk to 8-bit floating point (FP8) for deployment, which usually costs some accuracy. Quantization-aware training (QAT) simulates that FP8 rounding during fine-tuning so the model can adapt to it. Does a QAT-trained model end up more accurate in FP8 than a normally trained one?
  • Two methods, same everything else: both start from the same original model, use the same data, settings and number of steps, and train all parameters (no LoRA). The only difference is that QAT applies FP8 rounding to the model's main matrix layers in the forward pass (168 layers).
  • Same FP8 conversion for both: each trained model is converted with the same standard tool (llm-compressor FP8) and served with vLLM. The QAT rounding was checked to reproduce the converted weights exactly (100% of values on all 168 layers).
  • Data: GSM8K: 7,000 training, 473 validation and the full 1,319-question test set, split once and never changed.
  • Repeats: each method was trained 5 times with different random seeds (data order) for 3 epochs, and 5 times for 1 epoch, so results are averages rather than one lucky run.

3. How much accuracy does FP8 cost each method?

SettingNormal: BF16 → FP8QAT: BF16 → FP8
3 epochs+1.32 points lost+0.64 points lost
1 epoch+1.02 points lost+0.15 points lost

In the 3-epoch runs QAT models were also slightly better in plain BF16 (36.1% vs 35.3%), probably because QAT acts as a regularizer when the model overfits. In the 1-epoch runs that extra benefit disappears (both 36.1%), so the 1-epoch gain comes only from losing less accuracy in the FP8 conversion. Individual runs vary by a point or more, which is why the intervals are wide.

4. The more reliable signal: model loss

Accuracy on 1,319 questions is a noisy measure. The model's average loss on the correct answers (lower is better) is much more stable, and it shows a clear pattern:

SettingLoss increase from FP8, normalLoss increase from FP8, QATQAT smaller in
3 epochs+0.0097+0.00334 of 5 runs
1 epoch+0.0056+0.00295 of 5 runs

Converting to FP8 damages QAT-trained models clearly less, in both settings. This is the strongest evidence that QAT does what it is designed to do.

The untouched model scores higher than every fine-tuned model here. Fine-tuning on GSM8K's short human-written solutions did not improve this small model on this test. That does not affect the QAT-versus-normal comparison, because both methods start from the same model, but it means neither fine-tuned variant is better than simply using the original.

7. Conclusions and caveats

  • QAT consistently reduces the damage from FP8, shown most clearly by the loss: roughly half to a third of the increase, in nearly every run.
  • This translates into about +1 to +1.5 points of accuracy after FP8, positive in 8 of 10 runs across both experiments, but with one test set of 1,319 questions the 95% intervals reach zero, so we cannot claim a precise or guaranteed gain.
  • Limits: one small model, one maths dataset, one FP8 recipe, one GPU type (H100). The seeds change data order only, not the starting weights. FP8 results can differ slightly between GPU types.
  • Not measured here: speed. For a model this small, FP8 gave no measurable speed-up in a quick test (it is only about 36% smaller on disk), so speed was left out of scope.

Suggested next steps

  • Evaluate the same trained models on a second, larger maths test set to tighten the accuracy interval (the test-set size is now the main limit).
  • Try harder compression such as FP4 or INT4, where plain conversion loses much more accuracy and QAT has more to recover (larger models usually lose less to FP8, not more).
